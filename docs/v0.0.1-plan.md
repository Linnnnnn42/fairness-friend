# fairness-friend 0.0.1 设计提案

状态：用户已确认，0.0.1 已按本方案实现。本文保留设计时的提案措辞；实际接口和使用方法以 README 为准。

## 1. 目标和范围

实现一个供 Streamlit 前端调用的小型 Python 库：读取表格，指定敏感属性 A、真实标签 Y、模型预测 R，计算 Independence、Separation、Sufficiency，返回结构化结果。

这里分析的是数据中已有决策/预测的群体差异。完整分析需要 A、Y、R，并不包含训练模型生成 R。

0.0.1 建议支持：

- CSV、空白分隔文本；本地路径和文件流，包括 Streamlit UploadedFile。
- 按顺序指定列名，显式指定是否有表头、是否存在索引列。
- Y 和 R 为 0/1，1 表示所选正类；不自动推断业务含义。
- A 可以是二元或多类别离散属性；每个敏感属性独立分析。
- 一个全局 epsilon，默认 0.05，三类指标均按绝对概率差判定。
- 分组计数、概率、差距，以及 PASS / FAIL / UNDEFINED。
- 标准库 dataclass 返回对象，以及用于前端的 to_dict()。
- 使用 uv 管理依赖、锁文件、测试和构建。

暂不加入模型训练、偏差缓解、连续预测分数、回归、多分类 Y/R、自动分箱、缺失值填补、样本权重、交叉敏感群体、置信区间或绘图。指标对应表中的 ratio、ROC 等作为后续扩展，不在首版全部实现。

## 2. 当前仓库和调研结果

当前仓库已经采用 src/fairness_friend 布局、Python >=3.11 和 uv_build，只有初始化示例函数；pyproject.toml 的现有版本是 0.1.0，确认实现后改为用户要求的 0.0.1。

已经阅读指定的三个参考脚本，仅以其指标语义和输出信息为参考，不照搬实现。

已直接访问并读取用户指定的五个 Fairlearn 0.15.0 页面。三个页面最初通过网页工具访问失败，随后通过直接 HTTP 请求读取成功。也使用 Context7 检索了 Fairlearn、Pandas 和 uv 文档；版本行为以指定的 Fairlearn 0.15 文档为准。

重要结论：

- MetricFrame 提供分组基础指标和聚合差距，适合需要同时展示明细和汇总的前端。[评估流程](https://fairlearn.org/v0.15/user_guide/assessment/perform_fairness_assessment.html)
- 不应把 demographic_parity_difference 等已聚合的公平性指标放进 MetricFrame.metrics；这里应放基础分组指标。[MetricFrame](https://fairlearn.org/v0.15/api_reference/generated/fairlearn.metrics.MetricFrame.html)
- Separation 采用 TPR 差距和 FPR 差距的最大值，对应 equalized_odds_difference 的 worst_case 语义。[API](https://fairlearn.org/v0.15/api_reference/generated/fairlearn.metrics.equalized_odds_difference.html)
- Sufficiency 沿用参考脚本中两个条件概率的定义，由小型自定义基础指标配合 MetricFrame 实现。
- UploadedFile 是 BytesIO 子类，库只需要接受通用文件流，不需要依赖 Streamlit。[Streamlit 文件上传文档](https://docs.streamlit.io/develop/api-reference/widgets/st.file_uploader)

## 3. 推荐架构

数据流：

```text
文件 / UploadedFile
        ↓
读取表格与指定列名
        ↓
Dataset：DataFrame + 角色映射
        ↓
分析输入校验
        ↓
逐个敏感属性建立 MetricFrame
        ↓
分组指标 → 差距 → epsilon 判定
        ↓
结构化报告 → Streamlit 展示
```

建议只使用几个模块，避免首版引入插件系统、服务层或复杂继承：

```text
src/fairness_friend/
    __init__.py       # 导出公开 API
    models.py         # 数据对象、结果对象、状态枚举
    io.py             # 文件读取
    validation.py     # 校验及结构化异常
    assessment.py     # Fairlearn 基础指标、分析和判定
tests/
    test_io.py
    test_validation.py
    test_assessment.py
```

“读取”和“分析校验”分开，原始数据可以先载入预览，只有调用分析时才要求 A/Y/R 齐全。这也允许 German Credit 作为读取测试数据。

## 4. 数据对象和列名映射：建议确认的设计

推荐保留用户指定的列名作为 DataFrame 实际列名，用映射描述分析角色：

```text
Dataset
  data: pd.DataFrame
  column_map: dict[str, str]

data.columns = ["Sex", "Age", "Ethnicity", "Outcome", "Decision"]
column_map = {
  "A1": "Sex",
  "A2": "Age",
  "A3": "Ethnicity",
  "Y": "Outcome",
  "R": "Decision"
}
```

映射方向固定为“逻辑角色 → 用户指定列名”。分析通过映射取列，不要求敏感属性排列在最前面，也不假定最后两列必然是 Y/R。没有映射的普通特征列可以保留。

这是对原始需求的一个架构建议：DataFrame 不强制改名为 A1/A2/Y/R，避免数据预览与用户列名不一致。如果你希望 DataFrame 本身使用 A1/A2/Y/R，也可以采用规范列名，并将映射用于显示；确认时需要确定这点。

只读入原始数据时 column_map 可以为空或不完整；分析函数负责检查其完整性。针对已在内存里处理好的 DataFrame，也可以直接构造 Dataset，不必重新导出文件。

## 5. 拟定公开 API

以下只是接口草案，不是已实现的代码：

```python
read_dataset(
    source,
    *,
    column_names,
    format,                 # "csv" 或 "whitespace"
    has_header,             # 必须明确，避免误吞第一条样本
    column_map=None,
    index_col=None,          # 原文件中的索引列位置，如 0
    encoding="utf-8-sig",
) -> Dataset

analyze_attribute(
    dataset,
    attribute,              # 使用 column_map 中的角色名，例如 "A1"
    *,
    epsilon=0.05,
) -> AttributeAssessment

analyze_dataset(
    dataset,
    *,
    epsilon=0.05,
) -> FairnessReport
```

批量分析逐个调用同一内部计算逻辑。不能把所有 A 列一次性作为 sensitive_features 来代替循环，否则会变成交叉群体分析，与本次要求不同。

读取行为约定：

- column_names 的顺序对应排除显式 index_col 后的数据列；数量必须完全一致，名称非空且不能重复。
- CSV 使用逗号；whitespace 使用连续空白分隔，支持多个空格和 tab。
- 有表头时跳过原表头，并使用传入列名；无表头时第一行必须保留为数据。
- 显式传入 format，而不只靠扩展名判断；这也能读取 .data 文件。
- 文件流读取后恢复可定位流的原位置，不关闭调用方传入的流，支持前端重复调用。
- 空文件、字段数不一致、列名数不匹配给出明确异常；不静默截列或跳过坏行。
- 原始特征列允许字符串、数字和缺失值；分析用到的列另行严格校验。
- 空白分隔首版面向普通字段，不承诺支持带空格的复杂引号字段。

Pandas 的 names 和 header 行为需要显式控制，不能直接依赖默认推断。[Pandas CSV 文档](https://pandas.pydata.org/docs/reference/api/pandas.read_csv.html)

## 6. 三类指标的准确含义

令 Δ(p) = max_a p(a) − min_a p(a)。二元 A 时就是两组概率的绝对差，多类别 A 时仍能直接使用。

| 标准 | 分组基础指标 | 标准差距 |
| --- | --- | --- |
| Independence | selection_rate = P(R=1 \| A=a) | Δ(selection_rate) |
| Separation | TPR = P(R=1 \| Y=1,A=a)，FPR = P(R=1 \| Y=0,A=a) | max(Δ(TPR), Δ(FPR)) |
| Sufficiency | P(Y=1 \| R=0,A=a)，P(Y=1 \| R=1,A=a) | 两个条件概率差距的最大值 |

Sufficiency 的 R=1 分量是 PPV；R=0 分量是 false omission rate（FOR），不是 NPV。它等于 1−NPV，因此按组间绝对差判定时与比较 NPV 等价。只计算 PPV 不满足这里的完整 Sufficiency 定义。

实现建议：

- 使用 Fairlearn 的 selection_rate、true_positive_rate、false_positive_rate 和 count。
- 为 Sufficiency 定义两个小型基础指标，保持 y_true=Y、y_pred=R 的语义，不通过交换标签含义实现。
- 每个属性使用 MetricFrame 计算基础指标，用 difference(method="between_groups") 聚合完整有效的分组结果。
- 对条件分母单独计数，分母为零时显式标记未定义，不能依赖底层指标的零值默认行为。
- 用真实布尔条件计算 numerator、denominator，不从浮点概率反推计数。

## 7. epsilon 和状态

epsilon 必须是有限数值，范围 [0,1]；默认 0.05 表示 5 个百分点，不是相对变化 5%，也不是显著性水平。

每个基础分量按 gap <= epsilon 判定，通过数值比较容差处理恰好等于阈值的浮点误差，建议 abs_tol=1e-12、rel_tol=0。不能先格式化或四舍五入再判定。

基础分量状态：

- PASS：所有待比较群体都有定义，差距在 epsilon 内。
- FAIL：所有待比较群体都有定义，差距超过 epsilon。
- UNDEFINED：不足两个可比较群体，或任一应参与群体的条件分母为零。

每个属性的群体集合取自该属性在完整数据中出现的类别；在 Y 或 R 的条件子集内仍保留这个集合，不能忽略消失的群体。默认不推断整个文件中从未出现的类别；显式声明预期类别集合可作为后续扩展。

Separation / Sufficiency 聚合状态与参考脚本一致：任一分量 FAIL → FAIL；否则存在 UNDEFINED → UNDEFINED；全部 PASS → PASS。

只要某个必要分量未定义，该标准的完整 gap 就为 None；其他已定义分量及其状态仍保留。因此可能出现 status=FAIL、gap=None：已经有分量证明不通过，但完整最大差距尚不可计算。

库统一使用 PASS / FAIL / UNDEFINED。前端可以显示 FAIR(PASS) / UNFAIR(FAIL)，但其含义限定为“该指标在当前数据及 epsilon 下是否通过”，不生成一个覆盖三类标准的整体公平结论。[Fairlearn 常见指标说明](https://fairlearn.org/v0.15/user_guide/assessment/common_fairness_metrics.html)

## 8. 缺少 R：库负责校验，前端负责提示

推荐两边配合，但库是最终校验边界：

1. 读取阶段允许没有 R，返回可供预览的 Dataset。
2. Streamlit 可以在列选择阶段提示缺少 R，并禁用分析按钮。
3. 每次调用分析 API，库检查所需角色和实际列，防止直接调用绕过前端。
4. 缺少 R 角色时抛出 DatasetValidationError，携带 code="missing_roles" 和 missing_roles=["R"]；已映射但实际列不存在时，携带 code="missing_columns" 和 missing_columns 等字段。
5. 前端捕获异常，用自己的语言和界面展示信息；不依赖解析异常字符串。

输入不完整属于校验错误，不返回 FAIL 或 UNDEFINED，也不返回看似完整的报告。UNDEFINED 只用于合法输入中无法计算的统计量，例如某群体没有 Y=1 样本。

绝不能默认令 R=Y，也不随机生成 R。0.0.1 要求调用方补充已有预测；模型训练、数据划分和测试集预测留作另一个工作阶段。

## 9. 其他校验边界

- 文件中至少有一行数据。
- 批量分析至少映射一个敏感属性，Y、R 齐全；各分析角色不能意外映射到同一个列。
- 单属性分析校验选中的 A 以及 Y/R；批量分析校验所有声明的 A，全部有效后才计算。
- 选中的 A、Y、R 不允许缺失；不默默删除样本。
- Y/R 只接受 0/1 值（包括读取后等价的数值类型），拒绝 1/2、连续分数和未明确映射的字符串标签。
- A 为离散类别；连续年龄的分箱由调用方明确完成，不由库猜阈值。整数型年龄直接传入会被当作逐年龄类别，需要在使用说明中讲清。
- 只观察到一个 A 群体时，输入可以保留，但对应群体比较为 UNDEFINED，不能因为 max−min=0 而判 PASS。

## 10. 返回结构

推荐标准库 dataclass 加状态枚举，不引入额外建模框架：

```text
FairnessReport
  epsilon
  n_rows
  attributes: dict[角色名, AttributeAssessment]

AttributeAssessment
  attribute: "A1"
  column_name: "Sex"
  independence: CriterionResult
  separation: CriterionResult
  sufficiency: CriterionResult

CriterionResult
  gap: float | None
  status: PASS | FAIL | UNDEFINED
  components: dict[指标名, ComponentResult]

ComponentResult
  gap: float | None
  status
  reason: str | None
  groups: list[GroupRate]

GroupRate
  group: 原类别值
  numerator: int
  denominator: int
  value: float | None
  reason: str | None
```

例如 Separation 下的 components 为 tpr 和 fpr；Sufficiency 下使用 y_positive_given_r0 和 y_positive_given_r1，避免读者混淆条件方向。

分组记录采用列表，避免 JSON 对象键把类别值 0 和字符串 "0" 混在一起。to_dict() 将数值转为 Python 原生类型，未定义值为 None，序列化后为 null，不向前端泄漏 NaN。结果保留机器可读的原因码，例如 zero_denominator、insufficient_groups。

属性结果可以构成前端汇总表；GroupRate 可以构成明细表。库不打印文本，也不直接调用 st.write 或生成图表。

## 11. 测试数据与验收

已检查仓库中的测试数据：

| 文件 | 数据规模 | 使用方式 |
| --- | --- | --- |
| simple_data/model_outcome.csv | 100 行，导出索引列 + a1/a2/a3/y/r | 指定 index_col=0；验证三类完整分析 |
| german_credit/german.data | 1000 行，21 列，无表头 | 20 个特征 + 标签；测试混合类型空白分隔读取 |
| german_credit/german.data-numeric | 1000 行，25 列，无表头 | 24 个特征 + 标签；测试连续空格和前导空格 |

German Credit 两份文件末列均取 1/2，均没有 R。验收应确认“读取成功，直接分析被校验拦截”，不为了让测试通过而制造预测。原始 german.data 还包含性别与婚姻状态组合字段，年龄为数值；处理这些业务特征的规则由调用方决定。

对 simple_data 使用独立计数和精确分数核算得到以下基准（epsilon=0.05）：

| 属性 | Independence | Separation | Sufficiency |
| --- | --- | --- | --- |
| A1 / Sex | PASS，gap≈0.006803 | FAIL，gap=0.055 | FAIL，gap≈0.196970 |
| A2 / Age | FAIL，gap≈0.546715 | FAIL，gap≈0.559028 | PASS，gap≈0.025735 |
| A3 / Ethnicity | FAIL，gap≈0.188889 | FAIL，gap≈0.294444 | FAIL，gap≈0.207143 |

此表是调研时独立核算的预期结果，尚不是新库的测试通过记录。

确认实施后测试重点：

- CSV 有/无表头、空白文本、有/无索引列、BytesIO 重复读取和流位置。
- 指定列名、映射缺失、字段数错误、空文件、非法标签、缺失值、非法 epsilon。
- 两组和三组敏感属性的可手算样例；与 Fairlearn DP/EO 官方函数交叉核对有效输入。
- Sufficiency 的 R=0、R=1 两个分量及条件方向。
- 单一群体、条件空群体、所有预测相同、没有正标签等场景。
- 恰好等于 epsilon，以及略大于 epsilon 的判定。
- FAIL 与 UNDEFINED 混合时的汇总规则。
- 单属性与批量分析结果一致，结果可严格 JSON 序列化。

## 13. 待确认的核心选择

- DataFrame 保留用户列名，column_map 使用 A1/Y/R → 实际列名，而不强制重命名 DataFrame。
